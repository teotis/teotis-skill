# Cost Aware Delivery

Optimize the user outcome and total cost, using current capabilities and environment rather than model brands or assumed pricing. Compare direct work and tool reuse before delegating. Multiple installed platforms are not a reason to start external execution.

## Intelligence Adaptation Contract

- **Hard invariants**: Preserve outcome quality. Do not disguise unresolved difficult judgments as mechanical steps or format checks as semantic validation. Separate implemented, verified, and externally pending work. A brief does not expand authorization or require return-to-origin review. Do not launch or monitor external agents by default.
- **Mode contracts**: Normally deliver and verify necessary core improvements, then finish with an executable brief. Planning-only requests stop at planning. Coordination requires separate authorization and a suitable workflow.
- **User value priors**: Prefer durable reuse, solving shared hard problems, low handoff burden, and recipients who can start and close independently.
- **Adaptive heuristics**: Choose investigation depth, division, examples, batch size, and document structure by value and risk. Directly finishing a small task may be cheaper than creating a framework.
- **Examples and resources**: `references/task-brief.md` supplies budget, evidence, executor, networking, and calibration guidance; it is an adaptable aid, not a mandatory form.

## Capability Load

Self-probe: which investment prevents repeated errors, which decisions exceed the recipient's capabilities, does handoff cost exceed direct delivery, and can the recipient proceed independently? Skip|Delta for direct work or a small division; Light for clear boundaries; Full for uncertain root causes, dependencies, or capabilities. Never describe unverified prerequisites as available. Longer documents cannot repair a capability gap.

## Delivery and Division

Start from the actual outcome and existing assets. Total cost includes current effort, external execution, rework, communication, and user operations; avoid false precision. Handle root causes, critical design, difficult decisions, reusable engineering, and necessary verification where current capabilities suit them. Repetitive changes, content completion, batch runs, and local revisions can move to a capable recipient. Code is not inherently reserved for one platform, nor is content inherently delegable.

Reuse existing tools, data, and procedures. Implement reusable improvements in real execution paths; adding a prompt does not prove the underlying issue is solved. Use representative samples to establish the method and quality boundary without silently spending the entire batch budget. Resolve shared difficult judgments before handing off. If safe delegation remains impossible, reduce external scope or explain outcome/cost choices instead of lowering quality or forcing review loops.

## Budget and Value

Declare a first visible result, task-specific soft budgets, early stop conditions, and evidence locations. Budgets cannot bypass quality gates: preserve evidence and report partial/blocked when exhausted. Distinguish scope-accepted, first-value-landed, and integrated/published; batch completion is not the only value evidence.

## Task Brief and Closure

Use a durable location in the target project. Prefer one document; split only independent goals. A cold-start executor needs real inputs, verified baseline, reusable entry points, edit boundaries, first action, quality criteria, and result destination. State missing prerequisites and integration steps; do not pretend a temporary branch is already available in the recipient's environment.

Preserve completed decisions while allowing judgment inside the boundary. Specify proportionate failure handling, local skips, original preservation, and unknowns. Recipients validate their work and leave project-required results without an automatic receipt protocol or mandatory origin-model review.

For batch execution, also carry the [external resource lifecycle](task-brief.md#external-resource-lifecycle): placement admission and capacity for the output profile, what persistent workspaces, branches, claims, run directories, and evidence will be created or reused; who owns final integration; when resources may be released; and what must be preserved before cleanup. Prefer a project-provided read-only placement check when one exists and preserve its explicit allow, blocked, and gray-zone decision. Do not reinterpret a blocked result as an exception. Otherwise record capacity and volume suitability as unverified rather than inferring them from an old storage report.

Report what was delivered and verified, brief path, pending external scope, and real limits. Finish when the brief is usable. Do not create monitors, ledgers, reminders, return gates, or agents unless authorized. Brief delivery is not batch execution.

Specialized task planning or persistent orchestration is optional: if unavailable, this skill still delivers an independent brief. Switch workflows only when dependency closure, recovery, or durable coordination adds value. Task size alone does not justify escalation.
