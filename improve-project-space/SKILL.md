# Improve Project Space

Improve fit with actual user habits while keeping the project understandable, recoverable, and maintainable. Comparison projects provide evidence and counterexamples, not templates to copy blindly.

## Intelligence Adaptation Contract

- **Hard invariants**: Preserve authorization, privacy, user work, truthfulness, state authority, reversibility, and standalone operation. Default to analysis-only. Do not create or rewrite instructions, hooks, ledgers, layouts, migrations, or external systems without authorization covering the action. Historical reports or script existence do not prove current need. A Git checkpoint does not prove data or external effects can be restored; require proportionate recovery evidence.
- **Mode contracts**: Scaffold identifies the smallest foundation for a new project; Audit diagnoses friction and evolution risks; Migration turns an authorized direction into bounded, verifiable changes. Reuse existing authorization. An unresolved data/external-effect ambiguity blocks only dependent actions.
- **User value priors**: User goals outrank procedural completeness. Distinguish genuine preferences from tool-imposed workarounds. Reduce repeated operations and unnecessary governance without sacrificing integrity.
- **Adaptive heuristics**: Map user-project-mechanism relationships, then assess usage fit and architectural soundness. Depth and output adapt to project complexity.
- **Examples and resources**: `references/operation-and-evolution.md` expands recovery, interruption, maintenance, failure, and exit analysis. Project-native documents are comparison material to revalidate.

## Capability Load

Ordinary implementation or naming edits do not need this workflow. Rule wording/conflicts belong to a rule audit, which may be performed directly if no companion skill exists. Self-probe: does friction come from habits or boundaries, what mechanisms are really used, which authorities/recovery paths change, and which evolution risks could be missed? Skip|Delta for one observation; Light for targeted Audit; Full for consequential uncertainty in Scaffold/Audit/Migration. Read the bundled reference when persistent data, external effects, or cross-session state matter. Ordinary unknowns remain unknown; a one-off script need not gain an operations platform.

## Investigation and Action

1. Read entry points, README, rules, state surfaces, layout, checks, and current usage evidence.
2. Describe frequent, rare, exceptional, and explicitly rejected workflows and the objects/states/results actually maintained.
3. Inspect default paths, language, outputs, automation, boundaries, authoritative state, lifecycle, recovery, dependencies, and extension points.
4. For each candidate mechanism, identify the actual problem, evidence, case-specific assumptions, adoption/maintenance cost, and a smaller alternative.
5. Organize protection, friction repair, boundary changes, removal/downgrade, and pilots. Protect/Pilot/Defer/Reject can aid decisions; no-op is valid and empty categories need not be filled.
6. Separate preference, project goal, invariant, stage strategy, and case-specific example; mark verified/inference/unknown/missing evidence.
7. When authorized, use project-native implementation and protect existing edits. Validate real usage and affected failure/recovery paths. Checks and commits do not substitute for the goal.

## Standalone Investigation Contract

The local projection of investigation-kernel@v1 is a Project Fit Map with two axes: usage fit and architectural soundness. Safe operation by this skill does not prove reliability of the target project. Map current mechanisms, authorities, user paths, and recovery evidence; record coverage debt before recommending change. Do not treat another project's mechanism as proven need here. Missing tools or HTML enhancements permit a complete chat/Markdown result; missing recovery evidence forbids a recoverable claim.

## Output and Boundaries

Lead with project judgment, dominant friction, and architectural risk. Each recommendation needs current evidence, goal, applicability, benefit, maintenance cost, alternative, and disposition. Save durable reports only when review or handoff warrants them. Default to English. Do not replace specialist security scans or automatically initialize governance. Cross-project comparisons are leads, never permission to expand migration scope. A safety mechanism's implementation can change; low usage does not justify removing its protection.
