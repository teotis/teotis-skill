# Improve Project Rules

Make rules accurate, lighter, and compatible with capable judgment while preserving safety, truthfulness, authoritative state, user value, and standalone operation. Success is fit between rules and real failure modes, not minimum rule count or maximum scaffolding. Safety scaffolding is a floor, not an equally weighted optimization goal.

## Intelligence Adaptation Contract

- **Hard invariants**: Do not exceed authorization or weaken privacy, integrity, professional correctness, state authority, release, or irreversible boundaries. Rightsizing must preserve claim permission and discoverable full methods. Historical materials, script names, and old tests are not current assurance.
- **Mode contracts**: Analysis-only by default. Durable reports, decision queues, and apply handoffs are used when they improve review or implementation decisions. capability-focus emphasizes reducing overconstraint; scaffold-heavy is for explicit weaker-path concerns or evidence of unsafe skipping. Ask only about unresolved authorization or consequential tradeoffs.
- **User value priors**: Judgment, low user burden, and proportionate communication take priority over uniform formats or new control planes. English is the default output language.
- **Adaptive heuristics**: Scope, sampling, sections, and load labels adapt to the project. The five layers are lenses, not exclusive buckets. Check whether rules exclude no-op, unknown, partial states, direct answers, or project-specific better paths.
- **Examples and resources**: `references/audit-method.md` provides classification, load, hardness, interference, independence, consolidation, decision, and delivery guidance without requiring every form.

## Capability Load

Small wording edits use ordinary editing. Self-probe: what is the scope/authority chain, which rules interfere with valid outcomes, are safety/claim gates at risk, and what consequential issue would a shallow audit miss? Skip|Delta for one edit; Light for a narrow hardness/interference audit; Full for material uncertainty about permissions, strong claims, authority, or broad action. Ordinary gaps can remain unknown while work continues.

## Default Route

When repeated incremental edits, growing entry points, or overlapping proposals appear, consolidate before adding rules: map existing rule to failure mode, evidence, and user benefit; choose merge, downgrade, archive, or no-op. New rules compete only when existing ones cannot express a real missing boundary or benefit.

1. Read project instructions, native governance, and workspace state. Prefer existing registries, ledgers, checks, and archive semantics.
2. Separate narrative rules, executable enforcement, state authorities, mode protocols, and historical material. String counts do not count effective rules.
3. Apply the bundled five-layer, Hardness, Result-Interference, Capability Sensitivity, Load class, and Independence methods to valuable candidates. Prioritize conflicts and valid outcomes prevented by rules; treat missing scaffolding as a floor check. Record always-loaded text, probe-gated text, full-only methods, conflict risk, and receiver burden.
4. Deliver the smallest faithful surface: chat for a direct list; stable Markdown for durable multi-authority review; HTML only when relationships/interactivity improve understanding. Main conclusions emphasize judgment and reduced constraints; safety-floor gaps remain explicit coverage debt.
5. Batch only genuinely consequential human decisions, with evidence, impact, and supported recommendation. Use choices only when meaningfully distinct; do not create an approval queue for routine edits.
6. With existing implementation authorization, protect dirty baselines and switch to project-native implementation. This audit does not compete for primary ownership during implementation. Complete authorized edits, relevant checks, and necessary repairs; a first patch is not closure.

## Output

Lead with conclusion, risk, and navigation. Each substantial judgment links current evidence; inventories can live in an appendix. Durable audits may use a dated document under the project's reports/project-rule-improvement directory. Keep chat concise when an artifact exists, but preserve detail when chat is the main deliverable. Do not manufacture pending decisions. Report what changed, what was checked, and what remains unknown without mistaking static governance checks for live behavior.
